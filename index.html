The problem

Salesforce keeps the change. It forgets the stay.

Field History logs that a value changed and when. It never records how long the value lasted, who held the record meanwhile, or whether that time fell inside business hours. So the question your director asks on Monday has no report behind it.

How it works

Built so an admin can install, assign, and track a first object in about 25 minutes.

No developer and no schema changes in your org. Each new field you track is a record in Sojourn's setup, not a new column.

1

Install and assign

Install the package. Give admins Sojourn Admin, managers Sojourn Manager, and everyone else Sojourn User.

3 permission sets
2

Choose what to track

Pick objects and fields on the Sojourn Settings page. Case, Lead, and Opportunity start tracking as soon as you add them. Any other object needs one record-triggered Flow, copied from the template in the package.

About 10 minutes per object
3

Backfill your past

Sojourn builds intervals from the field history you already have, so your first report covers months, not minutes.

Backfill arrives in release 1 and reads the field history Salesforce still keeps, up to 18 months. Each month you wait, another month ages out.

Up to 18 months of history
4

Open the reports

In release 1, twenty report templates and four dashboards come with the package. Managers filter by owner, queue, or status in any report.

20 reports, 4 dashboards
