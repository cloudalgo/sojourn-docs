    Error Log

    The Error Log object records a change Sojourn could not turn into an Interval, with the Parent Id, Tracked Field, From and To Values, Occurred At, Error Type, and Message. Health Monitor users create the missing Interval, ignore, or resolve it, and the nightly reconcile retries Limit and DML errors. Commonly used as the error queue in the Health Monitor tab.

    API name: Error_Log__c

    Field API name Type Description
    Changed By Changed_By__c Lookup (User) The user whose save or job produced the change Sojourn could not record: the running user when the error was logged; for a nightly job, the admin who scheduled it. Written once by Sojourn; the Health Monitor shows it on each error.
    Help text: Who made the change, or which user's job was running, when Sojourn could not record it.
    Error Type Error_Type__c Picklist: DML, Limit, Config, BusinessHours, Unknown What kind of failure this row records, which decides how it is handled. Values: DML (an Interval write was refused), Limit (Sojourn stepped aside to keep the governor limit reserves), Config (a setup problem, such as a field or setting Sojourn cannot use), BusinessHours (business hours that could not be used, so calendar minutes were recorded), and Unknown (an unexpected error). The nightly reconcile retries New DML and Limit rows; a Health Monitor user can create the missing Interval for DML, Limit, and Unknown rows; Config and BusinessHours rows are fixed in Sojourn Settings. The Health Monitor filters by it.
    Help text: DML and Limit errors are retried each night. A DML, Limit, or Unknown error about one change can be recreated with Create Interval in the Health Monitor. Config and BusinessHours errors are fixed in Sojourn Settings, then marked Resolved.
    From Value From_Value__c Text (255) The Tracked field's value before the change that failed, as the Interval would have stored it, up to 255 characters. Blank for a record's first value, for errors not about one change, or when the value before was blank. Shown in the Health Monitor; a repair checks the change still follows the record's latest Interval.
    Help text: The value before the change Sojourn could not record.
    Message Message__c LongTextArea (32768) What went wrong, in words a screen may show; a job failure names the job and what stopped. Each nightly retry that fails adds a line (Retry 1: and the reason), and a repair that finds nothing to create adds its reason. Up to 32,768 characters, truncated beyond that. The Health Monitor shows it on each error.
    Help text: What went wrong and, after a retry or repair, why it was not recorded yet. Read it before choosing Create Interval, Ignore, or Resolve.
    Occurred At Occurred_At__c DateTime When the change happened: the time of the save, or for a Backfill, Catch up, or other job, the record's own time of the change. A repair opens the missing Interval at this moment, and the nightly retry waits until a row is at least an hour old. The Health Monitor sorts and filters errors by it.
    Help text: When the change Sojourn could not record happened. Create Interval starts the stay at this time.
    Owner Id Owner_Id__c Text (18) The 18-character Id of the record's owner (user or queue) after the failed change; for a change to the owner, the new owner. Blank on errors not about one record. A repair gives the missing Interval this owner.
    Help text: The user or queue that owned the record when the change happened.
    Parent Id Parent_Id__c Text (18) The 18-character Id of the tracked record whose change failed. Blank on errors not about one record, such as Config, BusinessHours, and job failures; those cannot be repaired or retried. The Health Monitor shows the record's name from it, and a repair or retry reads the record by it.
    Help text: The record whose change Sojourn could not record. Blank for setup and job errors.
    Parent Object Parent_Object__c Text (255) The API name of the Tracked object the failed change belongs to, for example Case. Blank on errors not about one record. The Health Monitor filters errors by it and links to the object's Sojourn Settings screen; a repair needs the object to be tracked still.
    Help text: The object of the record whose change failed, such as Case.
    Repaired Interval Repaired_Interval__c Lookup (Interval__c) The Interval created for this error, set when Create Interval in the Health Monitor or the nightly retry records the missing change and marks the error Resolved. Blank while the error is New, when it was ignored, or when it was resolved without a new Interval (the change was already recorded, or there was nothing to create).
    Help text: The stay Sojourn created to repair this error. Blank until a repair creates one.
    Retry Count Retry_Count__c Number (3, 0) How many times the nightly reconcile has retried this error and failed, a whole number from 0. Only New DML and Limit rows at least an hour old are retried, up to 200 a night, and retries stop after 3; the error then stays New for a Health Monitor user to repair, ignore, or resolve. Each failed retry adds its reason to Message.
    Help text: Failed nightly retries so far. After 3, Sojourn stops retrying and the error waits in the Health Monitor.
    Source Source__c Picklist: Trigger, Flow, Backfill-History, Backfill-Seed, Manual-Repair, Reconcile, Catch-Up, Omni-Channel Which capture path hit the error. Values: Trigger or Flow (live capture), Backfill-History or Backfill-Seed (Backfill), Catch-Up, Reconcile, Manual-Repair (a repair from the Health Monitor), or Omni-Channel. Blank on Config, BusinessHours, and job errors not raised by a capture path.
    Help text: Where the failed change came from, for example Trigger, Flow, or Backfill-History.
    Stack Stack__c LongTextArea (32768) The Apex stack trace of the exception behind the error, and for a job failure the platform's own message, up to 32,768 characters. Blank when no exception caused it. Only the Sojourn Admin permission set reads it, on the Health Monitor, the record page, and in reports; Sojourn Health Monitor has no access to it. Kept for support.
    Help text: Technical detail for support. Only Sojourn admins can read it.
    Status Status__c Picklist: New, Resolved, Ignored Where the error stands. Values: New (the default: waiting for a retry or a decision), Resolved (the missing Interval was created, the change was already recorded, or someone marked it fixed), and Ignored (someone chose to leave it). Only New rows are retried or repaired; Resolved and Ignored rows are kept for audit. The Health Monitor filters by it and its Ignore and Resolve actions set it.
    Help text: New errors wait for a nightly retry or your decision. Set Ignored to leave one, or Resolved once it is fixed; both are kept for audit.
    To Value Id To_Value_Id__c Text (18) For a change to an owner or lookup field, the 18-character Id behind the new value: the user, queue, or related record. Blank for other field types. A repair needs it to recreate the change and to tell whether the record's latest Interval already holds the value.
    Help text: For an owner or lookup change, the Id of the new user, queue, or record. Blank otherwise.
    To Value To_Value__c Text (255) The Tracked field's value after the change that failed, as the Interval would have stored it (a picklist's API value, the text, or an owner's or lookup's display name), up to 255 characters. A repair opens the missing Interval in this value.
    Help text: The value after the change Sojourn could not record.
    Tracked Field Tracked_Field__c Text (255) The API name of the Tracked field whose change failed, for example Status or OwnerId. Blank on errors not about one change. A repair needs the field to be tracked still on the object.
    Help text: The field whose change Sojourn could not record, such as Status.
