    Guide

    Track an object

    Choose an object and its fields in Sojourn Settings so Sojourn records how long each record spends in each value and with each owner.

    Salesforce admin About 10 minutes Since release 1

    You set up tracking in the Sojourn Settings tab of the Sojourn app. The page has a Sojourn menu on the left: Overview and Tracked objects today, with more screens joining it in later releases. Choose Collapse menu at its foot to fold it into icons; Sojourn remembers the choice in your browser. The tab needs the Sojourn Admin permission set; without it the page says so and shows nothing else. Changing the overview settings also needs the Customize Application permission, which system administrators have.

    Add an object#

    1. Open the Sojourn app and the Sojourn Settings tab, then Tracked objects in the menu.
    2. Choose Add object, search for the object, pick it, and choose Add object again. The list shows only objects Sojourn can track, so you never type an API name; objects you already track are marked Already tracked.
    3. On the object's screen, check the Tracked fields whose time in each value you want; they appear in the list beside the checkboxes, where Remove takes one off. Picklists, lookups, checkboxes, dates, and short text fields are offered; formulas, auto-numbers, and long text are not.
    4. Leave Track owner on to measure time with each user and each queue.
    5. Choose Save.

    Settings on the object's screen#

    • Status field and Closed values: the main status field and the values that mean the record is closed.
    • Name field: the field shown as the record's name on each Interval.
    • Business hours, or Business hours from a record field: the hours used for this object's business minutes.
    • Snapshot fields: up to 5 fields copied onto each Interval, for grouping reports by values such as priority.
    • Record types: track only these record types; leave empty for all.
    • Live values and its two minute fields: number fields on the record for the minutes in the current status and with the current owner. You can set them now; the job that keeps them current arrives in sprint 4.

    Check that capture is live#

    Each Tracked object shows a pill:

    Pill Meaning
    Tracked by package Case, Lead, and Opportunity: Sojourn's own triggers capture every change.
    Flow active An active Sojourn capture Flow runs on this object.
    Flow missing No capture Flow runs yet. Follow the steps on the object's screen.
    Flow unknown Sojourn could not read your Flows, usually because you lack View Setup and Configuration.
    Paused Capture is paused for a bulk import.
    Inactive The object is configured but not tracked.

    While an object's pill reads Flow missing or Flow unknown, its screen leads with four steps, and its fields and settings show as a summary until you choose Edit. On the Tracked objects list, Set up Flow opens those steps and Re-check Flows checks every object at once:

    1. In Setup, open Flows and the Sojourn Capture Template, then choose Save As, a new Flow. Keep "Sojourn" in the label.
    2. On the Start element, choose your object.
    3. In Sojourn: Capture Change, set the object for Record and Prior record to the same object.
    4. Activate the Flow, then choose Re-check on the object's screen. The pill turns to Flow active.

    If both a trigger and a Flow capture the same change in one save, Sojourn records it once. Each Interval records how the change arrived in its Source field: Trigger, Flow, or Catch-Up.

    Often missed. Setup objects such as User and Group cannot be tracked. Salesforce does not allow their changes and Sojourn's Intervals to be saved in one transaction, so Sojourn leaves them out of the list.

    Pause capture during a bulk import#

    Choose Pause on the Tracked object, in the list or on its screen, before a large import or update, and Resume afterwards. The list shows when the pause started. To stop tracking an object, turn off Active on its screen and choose Save; Turn on in the list brings it back. While paused, triggers and Flows skip the object, so the import runs without Sojourn's work. The catch-up job that replays the records changed during the pause arrives in sprint 4.

    Business hours for each Interval#

    Sojourn uses the first of these that is set:

    1. The Tracked field's business hours.
    2. A business hours field on the record, chosen in Business hours from a record field.
    3. The queue's entry in Queue Business Hours, while a queue owns the record.
    4. The Tracked object's business hours.
    5. The default on the Sojourn Settings overview.
    6. The org default business hours.

    If none applies, or the chosen business hours no longer exist, the Interval gets calendar minutes as business minutes, and a Tracking error of type BusinessHours tells you which setting to fix.

    Tracking errors#

    Sojourn never fails your users' saves. If it cannot record a change, it writes a Tracking error instead; the overview shows how many are open and links to them. Error Type tells you what happened:

    • DML: the Interval could not be saved.
    • Limit: the transaction was too close to a governor limit, so Sojourn stepped aside.
    • Config: a Tracked field names a field that does not exist.
    • BusinessHours: no usable business hours applied, so calendar minutes were recorded.
    • Unknown: anything else; the stack trace is kept for support.

    Each row keeps the record, field, and values, so the repair action in sprint 4 can replay it. To stop all capture at once, turn off Tracking enabled on the overview and choose Save settings.

    You are done when the object's pill reads Tracked by package or Flow active, and changing a Tracked field on a record opens a new Interval for it and closes the previous one.
