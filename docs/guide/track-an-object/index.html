    Guide

    Track an object

    Choose an object and its fields in Sojourn Settings so Sojourn records how long each record spends in each value and with each owner.

    Salesforce admin About 10 minutes Since release 1

    You set up tracking in the Sojourn Settings tab of the Sojourn app. The page has a Sojourn menu on the left, in three sections: Capture (Overview, Tracked objects), Time (Business hours, Goals), and Data (Retention and purge, Export settings). Choose Collapse menu at its foot to fold it into icons; Sojourn remembers the choice in your browser. The tab needs the Sojourn Admin permission set; without it the page says so and shows nothing else. Changing the overview settings also needs the Customize Application permission, which system administrators have.

    Add an object#

    Case, Lead, and Opportunity are tracked on every plan; for the quickest start, see Track Cases and open your first report. Every other object, custom or standard, is on the Plus plan and needs a capture Flow; see Free and Plus plans.

    1. Open the Sojourn app and the Sojourn Settings tab, then Tracked objects in the menu.
    2. Choose Add object, search for the object, pick it, and choose Add object again. The list shows only objects Sojourn can track, so you never type an API name; objects you already track are marked Already tracked.
    3. On the object's screen, check the Tracked fields whose time in each value you want; they appear in the table beside the checkboxes, where Remove takes one off and Business hours sets hours for that field alone (leave it on Use the object's to use the object's hours). Picklists, lookups, checkboxes, dates, and short text fields are offered; formulas, auto-numbers, and long text are not. Each field shows its API name under its label, here and in the snapshot fields, and the field lists read "Label (API name)", so two fields with the same label are never confused; search finds a field by either.
    4. Leave Track owner on to measure time with each user and each queue.
    5. Choose Save.

    Track only fields that everyone who reads Intervals may see. Sojourn copies a Tracked field's values into each Interval whatever the field-level security of the person who saved the record, and Sojourn User and Sojourn Site User can read those values, so a field you hide from a group shows to that group through Intervals and the timeline.

    The same goes for the other record values each Interval carries. Sojourn User can read the record's name (from the Name field below), the owner's name, the record type, and on Case, Lead, and Opportunity the values Sojourn copies there (Case Priority, Origin, and Type; Lead Source and Rating; Opportunity Stage), and the Interval list views show the record and owner names. Intervals are readable by everyone with Sojourn User, whether or not they can open the record, so choose a Name field such as the record number, not one that holds private text such as a Case subject. Snapshot fields and the Opportunity amount are not readable with Sojourn User. The Name field and Snapshot fields lists offer only fields you can read.

    An object can have up to 10 Tracked fields, the owner included. From the sixth, the picker reminds you that each field adds Interval rows for every record; at 10, it asks you to turn one off first. Short text fields are listed apart, under "Usually not useful for time in value".

    Each Tracked field has Start timing at the first value, on by default. When a record is created with the field blank, timing starts when the field first gets a value, so reports do not count the blank stretch before anyone filled it in. Turn it off to time the blank value from creation as well. The owner always starts at creation. Once a field has had a value, clearing it is a change like any other: the stay in the old value closes and a blank Interval opens, so time spent blank after a value is measured whichever way the switch is set.

    Under the picker, the Estimate shows about how many Interval rows a month your choice adds, and how much of your data storage a year that is. It counts the records you can see that were created in the last 30 days and their field history; fields without history are assumed to change once a month. "At least" means the count reached its limit, so the real number is higher.

    Settings on the object's screen#

    • Status field and Closed values: the main status field and the values that mean the record is closed.
    • Name field: the field shown as the record's name on each Interval.
    • Business hours, or Business hours from a record field: the hours used for this object's business minutes.
    • Snapshot fields: up to 5 fields copied onto each Interval, for grouping reports by values such as priority.
    • Record types: track only these record types; leave empty for all.
    • Live values and its two minute fields: number fields on the record for the minutes in the current status and with the current owner. The Live values job keeps them current on the schedule set on the Jobs card of the Sojourn Settings overview (see Live values and the jobs).

    When a record closes#

    A record counts as closed while its status field holds one of the Closed values. When the Tracked object's Closed Checkbox Field names a checkbox on the object, such as IsClosed on Opportunity, the record counts as closed while that checkbox is checked instead, and the closed values no longer decide. The list offers every checkbox on the object except Deleted (IsDeleted), which a live record never has checked. A name that is not a checkbox on the object, or IsDeleted, is ignored, with a Config row in the Error Log, and the closed values decide.

    While a record is closed:

    • every Interval open on it carries Record Closed, and so does every Interval that opens while it stays closed. An Interval that ends while the record is closed keeps the flag, and so does the one the reopen ends, such as the closed status;
    • the owner's stay ends at the close, with its minutes as usual, and no Owner Interval opens, even when the owner changes;
    • when the record reopens, a new Owner Interval opens for the owner it has then. Intervals still open after the reopen lose Record Closed, because the record is live again, and Intervals that open from then on do not carry it.

    History and Seed backfill, Catch up, and the nightly Reconcile follow the same rule; History reads the deciding field's history, and without it a closed record counts as closed since its last change (see Backfill). Reconcile also puts Record Closed in step on the open Intervals of the records it checks and ends their open owner stays, at the entry of the Interval that holds the closed value when there is one, otherwise at the record's last modification.

    Check that capture is live#

    Each Tracked object shows a pill:

    Pill Meaning
    Tracked by package Case, Lead, and Opportunity: Sojourn's own triggers capture every change.
    Flow active An active Sojourn capture Flow runs on this object.
    Flow missing No capture Flow runs yet. Follow the steps on the object's screen.
    Flow unknown Sojourn could not read your Flows, usually because you lack View Setup and Configuration.
    Paused Capture is paused for a bulk import.
    Inactive The object is configured but not tracked.

    While an object's pill reads Flow missing or Flow unknown, its screen leads with four steps, and its fields and settings show as summaries until you choose Edit fields or Edit settings. On the Tracked objects list, Set up Flow opens those steps and Re-check Flows checks every object at once:

    1. In Setup, open Flows and the Sojourn Capture Template, then choose Save As, a new Flow. Keep "Sojourn" in the label.
    2. On the Start element, choose your object.
    3. In Sojourn: Capture Change, set the object for Record and Prior record to the same object. Pass the prior record on every save, as the template does: when some saves in one batch pass it and others do not, Sojourn records each correctly but in two passes, at twice the queries.
    4. Activate the Flow, then choose Re-check on the object's screen. The pill turns to Flow active.

    Keep your copy a record-triggered Flow that runs after the save, as the template is: it runs in system context, so it records every user's changes. If you call Sojourn: Capture Change from a screen Flow or another Flow that runs as the user, give those users access to the action's Apex class (ChangeCapture) through a permission set of your own; only Sojourn Admin includes it, and without it the Flow fails for everyone else. Grant it with care: the action records the field values and change time of the record the Flow hands it, without reading the record again, so a Flow that changes that record variable before the action, run by a user with the class, records Intervals for values the record never held.

    If both a trigger and a Flow capture the same change in one save, Sojourn records it once. Each Interval records how the change arrived in its Source field: Trigger, Flow, or Catch-Up.

    Often missed. Setup objects such as User and Group cannot be tracked. Salesforce does not allow their changes and Sojourn's Intervals to be saved in one transaction, so Sojourn leaves them out of the list.

    Pause capture during a bulk import#

    The Tracked objects list shows each object's Tracked fields, whether it tracks the owner, its capture pill, and where its business hours come from: named hours, From record field, or Sojourn default.

    Choose Pause on the Tracked object, in the list or on its screen, before a large import or update, and Resume afterwards. The list shows when the pause started. To stop tracking an object, turn off Active on its screen and choose Save; Turn on in the list brings it back. A notice at the top of the page says each took effect, for example "Case is paused. Changes made now wait for Catch up." While paused, triggers and Flows skip the object, so the import runs without Sojourn's work. After you resume, the list says "Changes made while paused wait for Catch up". Choose Catch up to replay the records changed during the pause: each gets its Interval at the time it changed (its last modification, or its creation if it was created during the pause), and values Sojourn already holds are skipped, so running it twice is safe. A field with no open Interval gets its first one only on a record created during the pause; on older records it waits for the field's next change, and a blank field timed from its first value gets nothing until it has one. One catch up runs at a time across all objects: while one is going, the list says "Catch up is running" in place of the button, and starting another is refused. If part of the run is skipped or fails (for example, tracking was turned off, or the Error Log records a Limit or DML error), the list keeps offering Catch up, so you can run it again. If you pause the object while a catch up runs, even briefly and resumed before it ends, the pause window is kept for the next catch up. Pausing again before you catch up keeps the earlier start, so one catch up covers both pauses. The result of the last catch up is kept in the Tracked object record's Catch Up Message field, apart from the last backfill result, so a catch up never hides how the backfill went; the object's screen lists both in its Backfill card, as Last backfill and Last Catch up.

    Importing past records. When an import sets each record's Created Date (Salesforce's Set Audit Fields upon Record Creation), Cases, Leads, and Opportunities start their first Intervals at that date. A Flow cannot tell a new record from an update, so for other objects also set Last Modified Date to the Created Date in the import; otherwise their first Intervals start at the import.

    Backfill past Intervals#

    A new object starts with the next change. To give existing records their Intervals, use the Backfill card on the object's screen; see Backfill past Intervals.

    Live values and the jobs#

    The Jobs card on the overview schedules Live values, Reconcile, and Summaries. See Run the jobs for when each runs and what it does.

    Business hours for each Interval#

    Sojourn uses the first of these that is set:

    1. The Tracked field's business hours.
    2. A business hours field on the record, chosen in Business hours from a record field.
    3. The queue's entry in Queue Business Hours, while a queue owns the record.
    4. The Tracked object's business hours.
    5. The default on the Sojourn Settings overview.
    6. The org default business hours.

    If none applies, or the chosen business hours no longer exist, the Interval gets calendar minutes as business minutes, and an Error Log row of type BusinessHours tells you which setting to fix.

    The Error Log#

    Sojourn never fails your users' saves. If it cannot record a change, it writes an Error Log row instead; the overview shows how many are open and opens the Health Monitor, which explains each error and fixes it. See Watch Sojourn in the Health Monitor. To stop all capture at once, turn off Tracking enabled on the overview and choose Save settings.

    You are done when the object's pill reads Tracked by package or Flow active, and changing a Tracked field on a record opens a new Interval for it and closes the previous one.
