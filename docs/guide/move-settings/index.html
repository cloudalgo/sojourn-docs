    Guide

    Move settings between orgs

    Export Sojourn settings from a sandbox as a file, check the import in production, then apply it.

    Salesforce admin About 10 minutes Since release 1

    Set Sojourn up once in a sandbox, then move the settings to production, or to another sandbox, as a file.

    What the file carries#

    Tracked objects with their settings, Tracked fields, goals, queue business hours, Tracking enabled, and the default business hours. Retention is not in the file: production keeps what you chose there.

    Business hours are written by name and queues by developer name, because record Ids differ between orgs.

    Export#

    In the org you are copying from, open Sojourn Settings, then Data, then Export settings, and choose Export. Sojourn saves the file, named like sojourn-settings-2026-10-12.json, to your Files and opens it. Download it from the preview.

    Check the import#

    In the org you are copying to, open the same screen and choose Choose file. Sojourn reads the file and lists What the import will do: each Tracked object, Tracked field, goal, queue, and setting it will create, update, turn off, or skip, and why. Nothing has been changed yet.

    • An object or field this org does not have stops the whole import, and nothing is written. Add the field, or remove it from the source org, and export again.
    • A queue or business hours this org does not have is skipped, with the reason; the rest still imports.
    • A file that is not a Sojourn settings file, or is from a later format, is refused.

    Apply#

    Choose Apply. Everything in the list is written together, or nothing is.

    Turn on Replace what is here before checking to make this org match the file: Tracked fields and goals that are not in the file are turned off. Nothing is deleted, and Tracked objects that are not in the file are left as they are.

    You are done when

    • Choosing the same file again lists nothing to change.
